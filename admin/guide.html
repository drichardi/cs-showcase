Putting student work on the CS showcase

The teacher dashboard adds, changes, shows and hides the student projects on the showcase site. You never touch code or GitHub. Everything here takes a few minutes, and nothing you do can break the site.

Three rules

  1. Only show work the student agreed to share. New projects start hidden. Ticking "Show it on the site" asks you to confirm the student(s) agreed.
  2. First name and last initial, like Noa P. Never a full name.
  3. Hidden is safe. A hidden project is saved but not on the site. If you're unsure, leave it hidden.

Signing in

Open the dashboard and sign in with your Punahou Google account. Only CS teachers on the dashboard's list can get in; ask a colleague who manages it to add you.

A sign-in lasts 8 hours in that browser tab. If it runs out while you're working, a "Sign in again" box appears over the page. Sign in there and carry on; nothing you've typed is lost.

Once you've signed in, a Public site | Dashboard switch at the top of every page takes you between the showcase as visitors see it and the dashboard.

Add one project

Press Add project. The page has four parts.

  1. Where it goes: the course, the assignment (or "New assignment…"), and the term.
  2. The work, one of:
    • p5 sketch: in the p5 editor choose File → Download, then drop that zip on the page. A sketch folder works too. It starts playing in a preview, just as it will on the site.
    • Link: paste a p5 editor, Scratch or CodePen link. For an itch.io game, use the address from the game's "Embed game" settings, not its page.
    • Pictures or video: for work that isn't interactive. Pick which picture is the cover.
  3. Details: a title, the student(s) (press Enter after each name), a sentence or two on what it is, and optional "How to use it" steps, one per line, like Click to jump. Those show as "Try it" beside the project. Links to a write-up or a video are optional too.
    On the site sets three things, all optional:
    • Visitors can play it here (on by default). Untick it to show just the cover and links, with no Play button or "Try it" steps.
    • Code link: "View code" goes to the sketch's own code, or the p5 editor for a p5 editor link. Choose "Link to…" for somewhere else, like GitHub, or "No code link".
    • See it in action: a page where the project runs, like itch.io.
  4. Publish: choose the cover (a sketch gets a screenshot automatically; for a link, upload a picture), tick "Show it on the site" if the student agreed, and press Publish. The list under the button says what's still missing.

It's on the site about a minute later; the page tells you when, with a link to see it. A project can be up to 25 MB. A bigger game belongs on itch.io, added here as a Link.

Add a class set

For a whole class's sketches for one assignment, press Add several.

  1. Pick the course, assignment and term once, for all of them.
  2. Drop in the students' zips, or a folder of them. A Google Classroom or Drive download works as it is, zips inside zips included. Each sketch found becomes a row.
  3. Check each row. Titles and names are guessed from the file names, so fix any that are wrong (names are tidied to Noa P. when you leave the box). ▶ Preview plays that sketch.
  4. Tick Show on the ones to put on the site (or "Show all"), and tick the one consent box.
  5. Optional: "How to use it" steps, shared by all of them.
  6. Press Publish. Up to 40 at a time.

Anything that wasn't a sketch (a student who handed in a document, a zip that won't open) is listed separately, so you know who to follow up with. Add descriptions and covers to each project later with Edit.

Change, show or hide

Each project card has buttons:

Edit
Change the details or the cover, or upload a new version of the sketch.
Show on site / Hide
One click, after a confirmation. Hiding takes it off the site but keeps it, so you can show it again any time.
Set up
A sketch is in the repo but has no details yet, so it isn't on the site. Fill them in.
Fix
Its details file has a mistake (usually from editing by hand). Saving the form writes a fresh one.

Assignments: press New assignment to set one up before any work is added: its course, name, description and order. It appears on the site once it has work that's shown. To change one, choose a course and an assignment above the list, then Edit assignment. The description shows on the course page above its projects; "Order" decides which assignment comes first.

Removing a project for good isn't in the dashboard yet. Hide it, and ask a colleague who manages the repo if it really must go.

Finding things

Search by title, student or assignment, or filter by course, assignment and status:

  • On the site and Hidden are what they say.
  • Needs details: a sketch waiting for Set up. Needs fixing: press Fix.
  • Needs attention shows only projects with something to fix, like missing student names or a link with no cover. "Could add" on a card is a suggestion, never required.

If something goes wrong

"Someone else changed this project"
A colleague saved it while you had it open. Go back to Projects, open it again, and redo your change.
"Saved, but publishing failed"
Your work is safe in the repo; only the site's update didn't finish. Don't add it again (that would make a second copy). Ask a colleague who manages the repo; the "See what happened" link shows them why.
"Not saved", or the server didn't answer
Check your connection and press Publish again. Nothing is half-saved: it all saves or none of it does.
A sketch's cover is blank or odd
Some sketches draw nothing until clicked. Open Edit and upload a screenshot as the cover.
A file name "can't be used here"
Rename that file in the sketch (letters, numbers, spaces, - and _ are fine), download it again, and re-add it.
Over 25 MB
Put the game on itch.io and add it as a Link.
A "Test mode" banner
The dashboard is being worked on and saves go to a practice copy, not the site. Wait for it to go.

Every save is recorded in the student-work repo with your name and what changed, so any mistake can be undone there.
